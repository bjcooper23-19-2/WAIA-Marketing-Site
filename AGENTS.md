# Codex instructions for WAIA Marketing Site

Read README.md and relevant project documentation before making changes. Preserve WAIA's positioning, approved claims, branding, buyer journey, accessibility and conversion paths.

## Shared operating system

Follow Investigate → Implement → Release from bjcooper23-19-2/codex-operating-system.

For material visual design work, use UI/UX Pro Max alongside apple-inspired-design from the shared operating system.

Apply Apple-inspired design principles to create a refined, premium editorial experience:
- Confident typography and clear hierarchy.
- Generous whitespace and deliberate proportions.
- Subtle depth, restrained colour and consistent alignment.
- High-quality responsive presentation and accessible controls.
- Purposeful transitions and refined visual details.

Preserve WAIA's established brand identity. Avoid generic SaaS layouts, excessive visual effects and unnecessary redesigns.

Prioritise buyer comprehension, credibility and clear conversion journeys. Never introduce unsupported commercial or customer claims.

Use No AI Slop for newly created or materially revised public copy.

Review rendered desktop and mobile pages when practical and report any limitations.

Do not copy shared skills into this repository. Do not merge, deploy or publish without explicit human approval.

## Proportionate delivery (shared standard)

Follow [shared proportionate delivery](https://github.com/bjcooper23-19-2/codex-operating-system/blob/main/docs/proportionate-delivery.md). Classify changes as **Fast**, **Standard** or **Protected** by potential consequence, not file count. Use an appropriately light Investigate → Implement → Release workflow. Fast changes need no separate issue if clearly specified; maintain a focused branch, PR, relevant checks and explicit human approval. Standard changes need acceptance criteria and affected-journey validation. Protected changes need explicit risk assessment, failure-path and regression evidence, and stronger verification. Never bypass repository CI or existing security requirements.

WAIA marketing: prioritise buyer comprehension and conversion. Treat privacy/tracking consent, legal terms, submissions/integrations and material pricing or commercial claims as Protected; small copy and styling fixes can be Fast.

Before implementing significant features, state the user problem, evidence versus assumption, smallest useful intervention and success indicator. Prefer removing unnecessary user work over adding another feature. Only invoke specialist design/editorial skills where relevant. Use one concise handoff: **what changed and why; checks performed; remaining risks; decision needed**. Keep detailed evidence in PRs rather than long chat reports. For the next 10–15 changes, note risk classification, human supervision effort, rework and escaped defects where known.
